# PostgreSQL enum migrations

When a migration creates a table with a new named PostgreSQL enum, create the enum explicitly with `checkfirst=True`, use the enum with `create_type=False` in the table definition, and drop it with `checkfirst=True` after dropping the table on downgrade.

**Why:** PostgreSQL named enum types outlive a dropped table unless explicitly removed. A generated migration may recreate the table's enum unconditionally, causing a duplicate-type failure after a downgrade/re-upgrade or an interrupted local migration cycle.

**How to apply:** Inspect every autogenerated migration that introduces a native enum. Verify an upgrade from its parent and a downgrade/upgrade round-trip against a development database before delivery.
