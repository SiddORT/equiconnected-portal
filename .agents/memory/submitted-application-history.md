---
name: Submitted application history
description: Interpret historical provider application answers without inventing submissions.
---

Application review must distinguish an absent historical answer from an explicit false or zero. Do not infer a submitted Stable visit answer from a legacy visit classification, or treat a missing consent timestamp as proof of refusal.

**Why:** Older applications predate some current signup fields; classification and defaults cannot establish what an applicant actually submitted.

**How to apply:** Show missing answers as Not provided, preserve explicit No and 0, and display acceptance timestamps only when stored. Resolve saved catalog selections even when their master records have since been deactivated; deactivation changes future choices, not historical submissions.
