==================================================
1. PURPOSE
==================================================

Admin must be able to invite:

- Hospital
- Clinic
- Doctor

to complete their provider information.

The recipient receives an email containing a secure invitation link.

The recipient opens the form, completes the required information, and submits it.

The submitted provider must then be available to Admin for review.

The provider must NOT automatically become publicly visible.

Only after Admin approval should the provider become eligible for publication and appear in the public Providers listing.

==================================================
3. INVITATION VS PROVIDER VS USER
==================================================

Keep these concepts separate.

Invitation:

Represents an invitation sent to a person/email.

Provider:

Represents the Hospital, Clinic or Doctor.

User/Account:

Represents an authenticated person who may eventually manage a Provider.

Do NOT store login credentials on the Provider table.

Do NOT use the invitation as a user account.

Do NOT automatically create permanent user authentication credentials when sending an invitation.

==================================================
4. INVITATION TABLE
==================================================

Create a normalized invitation table using PostgreSQL.

It should support information such as:

- id
- provider_id where applicable
- provider_type
- recipient_email
- invitation token/hash
- status
- expires_at
- sent_at
- accepted_at
- completed_at
- created_by
- created_at
- updated_at

Use proper PostgreSQL types.

Do not store invitation information as JSON.

Do not store raw invitation tokens if a secure hash-based token approach is appropriate.

==================================================
5. INVITATION STATUS
==================================================

Use controlled statuses.

At minimum:

- PENDING
- ACCEPTED
- EXPIRED
- CANCELLED
- COMPLETED

The provider's lifecycle/status is separate.

Example:

Invitation:
COMPLETED

Provider:
UNDER_REVIEW

Publication:
UNPUBLISHED

Do NOT equate invitation completion with provider approval.

==================================================
6. SECURE INVITATION TOKEN
==================================================

Invitation links must use cryptographically secure random tokens.

Requirements:

- High entropy
- Single use
- Expiration
- Server-side validation
- Invalidated after completion
- Cannot be reused
- Cannot expose database passwords/secrets
- Cannot contain sensitive provider information

Do not use predictable IDs as invitation tokens.

Do not put passwords in invitation URLs.

==================================================
7. INVITATION URL
==================================================

Create a public invitation route such as:

/provider/invite/:token

The actual route may follow the existing frontend architecture.

The link should open the appropriate provider form.

The server must validate the token before exposing sensitive invitation information.

==================================================

30. RESEND INVITATION
==================================================

Admin can resend a pending invitation.

When resending:

- Do not create uncontrolled duplicate invitations
- Apply a clear token/expiration strategy
- Invalidate the previous token where appropriate
- Generate a new secure token
- Update sent_at
- Update expiry

Prevent invitation abuse.

==================================================
31. CANCEL INVITATION
==================================================

Admin can cancel a pending invitation.

Cancelled invitations cannot be used.

Do not delete the historical invitation record.

Use status:

CANCELLED

==================================================
32. INVITATION EXPIRY
==================================================

Invitations must expire.

Use a configurable expiration period.

Do not hard-code a business duration if the application already has configuration infrastructure.

Expired invitations cannot be accepted.

Admin may resend a new invitation.

==================================================
