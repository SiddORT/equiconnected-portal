## Filter scope audit

The page accepts URL-backed filter values, but sends a filter only to report domains where it has a real relationship. The backend schemas validate enum, UUID, length and date bounds; backend repository conditions determine actual count scope.

| Filter family / visible controls | Scope actually used by the shipped report |
| --- | --- |
| Provider type | Provider inventory, matching provider-linked reviews/ratings, applications and invitations; also applicable provider rankings/profile views. It does not narrow sitewide page views, member registrations, enquiries or subscribers. |
| Provider status / Publication | Current provider inventory and matching provider-linked review/rating/ranking rows. These lifecycle filters are not application or invitation-status filters. |
| Provider name search | Search field in Provider popularity (and the More filters provider-name field on Reviews & feedback); server matching is case-insensitive against provider name. |
| Listing country / Listing city | Exact case-insensitive recorded provider-listing geography on the Providers section; provider ranking deduplicates through relationship existence and does not fan out rows. This is not visitor geography. |
| Provider record / Specialization deep-link values | Supported filter keys for matching provider reports; raw record-ID inputs are not shown as ordinary filter fields. Existing deep-link values appear as removable active filters. |
| Member role / Verification / Account | New-member registration totals and selected registration-cohort state. These values do not change unrelated sections. |
| Application status | Application reports only. |
| Invitation status | Invitation reports only (applied to records using current invitation status). |
| Review moderation / Star rating | Provider-review submission, review-state, rating and provider-ranking data where applicable. Does not filter private platform feedback. |
| Feedback category / Feedback state | Private feedback reports only. A withdrawn selection is distinct from active feedback moderation states. |
| Enquiry type | Enquiry total, series and type breakdown only. |
| Subscriber type | Subscriber total, series and type breakdown only. |
| Date range / Group by | Shared report window and time-series bucketing; does not redefine a metric’s event timestamp or convert a current snapshot into historical data. |

The user-interface transformations are in `AnalyticsPage.tsx` (`queryFor`, `queryForDomain`, `queryForMetric`). Actual backend conditions are in `admin_analytics_repository.py`; request/response definitions are in `backend/app/schemas/admin_analytics.py`. `frontend/src/pages/admin/AnalyticsPage.test.tsx` covers provider/application/invitation scope and ensures provider filters do not leak into sitewide traffic exports.

## Reporting calculations and worked examples

The following examples explain the implemented contracts; their numbers are arithmetic examples, not claims about the current database.

- **Inclusive local dates:** selecting 2026-03-08 in `America/Los_Angeles` means local midnight through the next local midnight. The backend converts that to `[2026-03-08 08:00 UTC, 2026-03-09 07:00 UTC)`, a 23-hour day because daylight saving time changes. Do not add a fixed 24 hours or shift a calendar day based on the viewer’s laptop timezone.
- **Equal-length comparison:** for a 7-day selected period with 120 eligible events and a fully covered preceding 7-day period with 100, the displayed change is `(120 - 100) / 100 × 100 = +20%`. If the previous count is zero, the percentage is unavailable (`zero_baseline`), not infinity or 100%. Business-source comparisons are also unavailable when their history is not known to be complete.
- **Partial new traffic:** if tracking starts partway through a 30-day window, traffic is calculated only for tracked dates and marked partial; earlier days are unavailable, not synthesized as zero. Its series starts at the first tracked date. A date within known tracking coverage with no events may be a real zero.
- **Visitor estimates:** daily estimates of 8, 10 and 7 sum to 25 visitor-days across three days. The reporter must not call that “25 unique people”; a browser estimate is not a verified person count.
- **Registration cohort:** if 20 public member accounts were created in a selected week and 16 are currently verified, the period addition is 20 while “Verified in selected cohort” describes the present verification state of those same 20 accounts. One account with both public roles contributes once to the account total and the exclusive “Both” group; role-assignment totals can overlap.
- **Applications:** if an application was created before the selected week but approved during it, it is not a new application in that week; its decision belongs to the week because decisions use `reviewed_at`. Application-created cohorts are separately classified by their current status.
- **Provider reviews and feedback:** a newly created review counts as an initial submission; an edit/action is reported separately. An undeleted hidden rating is eligible alongside a published rating, while pending, rejected and deleted ratings do not contribute. Private feedback averages/counts are not merged into provider ratings; withdrawn feedback is separated from active backlog state.
- **Enquiries and subscribers:** a durably stored enquiry is counted regardless of notification-email delivery. Repeating a subscription attempt for an email that already has a stored unique subscription is not another new subscriber.
- **Provider ranking:** ranking columns do not share a time basis: profile views and initial review submissions use the selected period; current average rating, eligible rating count and saves are current values. Providers with no tracked period views can still appear. Before tracking coverage, views are unavailable rather than zero.
- **CSV truncation:** a breakdown that flattens to 5,130 data rows exports at most 5,000 and appends the explicit notice. The notice must be retained and the report narrowed before the exported rows are treated as the full result.
